# FanHive 競合優位性（忖度なし・チーム共有用）

> ピボット後アプリが、既存まとめサイト／公式ECより本質的に優れている理由。ピッチの「競合優位性」スライドにも流用可。

## 一言で（チームで共有する核）

**FanHive ＝ 推し活の情報を「構造化して・勝手に貯まり続けて・自分用に通知して・ワンタップで買える」レイヤー。公式ECと既存まとめサイトの“間”を埋める。**

ECは「自社の商品を売る」、まとめサイトは「読ませる」。どちらも「複数作品 × 複数販路の予定とグッズを、自分用に、最新で、一箇所で」を満たせない。そこが空白。

## 比較（◎○△✕／正直評価）

| 観点 | 公式EC（animate等） | 既存まとめ/ブログ | FanHive |
|---|---|---|---|
| 作品をまたぐ | ✕（自社商品のみ） | △（サイト次第） | ◎ |
| 販路をまたぐ | ✕ | ○（リンク列挙） | ◎ |
| 見逃し防止（予定通知） | △（再入荷通知程度） | ✕ | ◎ |
| 構造化（絞込・状態・在庫） | ◎（自社内） | ✕（文章） | ◎ |
| 鮮度・更新が続く | ◎（自社） | ✕（更新が止まる） | ◎（AI＋コミュニティ） |
| パーソナライズ | △ | ✕ | ◎ |
| 情報入力のスケール | ◎だが自社のみ | 人力で限界 | ◎（AIで自動化） |
| 双方向（ファンが追記） | ✕ | ✕ | ◎ |
| 購入の完結 | ◎ | ✕（リンクだけ） | △（送客＝決済は他社）← ECが上 |
| 新作・コラボの発見 | △ | ○ | ◎ |

※「購入の完結」だけ FanHive が劣る。欠点ではなく設計（買う場所はECに任せ送客で稼ぐ）。ただし収益がECのアフィ提供に依存する弱点でもある（下記）。

## 顧客の課題 → どう解決するか（インタビュー直結）

| ファンの困りごと | FanHiveの機能 | 解決 |
|---|---|---|
| 受付開始・先着・発売を見逃す | パーソナライズ通知（受付開始/発売、リードタイム一括設定） | 先着を逃さない |
| 複数作品・複数販路を一元管理できない | 作品横断＋販路横断の集約、フォロー | アプリ1つで完結 |
| 自分で入力するのが面倒 | AI入力（共有/URL/写真）＋画像自動取得＋複数分割 | 入力ほぼゼロ |
| 受注/発売/在庫が分からない | 5段階の状態バッジ＋在庫追記ログ | 一目で判別 |
| どこで買えるか探すのが手間 | 販路リンク（アフィ）を複数並べる | ワンタップで購入へ |
| 情報の正確性が不安 | 共同編集＋編集履歴＋重複検知＋信頼度ティア | 自己修正する正確性 |

## なぜ既存まとめサイトより本質的に強いか（3点）

1. **人力 vs AI＋コミュニティ**：まとめサイトは手作業で更新が止まりスケールしない。FanHiveは1ソースをAIが構造化、ファンが追記して勝手に貯まり・自己修正する。
2. **文章 vs 構造化データ**：ブログは読むだけで絞り込めない・通知できない。FanHiveは日付/状態/販路/在庫がデータなので通知・絞り込み・パーソナライズが効く。
3. **収益が回る → 続く**：個人まとめは儲からず止まる。FanHiveはアフィリエイト＋ゲーミフィケーションで貢献が報われる＝情報が枯れない。

## 忖度なしの弱み（直視すべき）

- **コールドスタート**：最初に誰が埋めるか。最大の壁。AI入力・ゲーミフィケーション・作品単位コミュニティで攻めるが未証明。
- **アフィリエイトの穴**：直販・一番くじ・イベント物販はアフィプログラムが無い＝リンクも収益も付けにくい。B2B送客で取りに行くが手間。
- **送客モデルの宿命**：購入はEC依存。ECがアフィを閉じたら収益が脆い。
- **SEO新規参入の不利**：検索流入は既存サイトが先行。
- **正確性は永遠の課題**：共同編集で減らせるがゼロにならない。

→ 強み＝「空白を埋める構造 × 自己増殖 × パーソナライズ」。弱み＝「立ち上げと収益のEC依存」。ここを正直に言えるチームが強い。
