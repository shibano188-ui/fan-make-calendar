FanHive ─ ウィジェットの品揃え案 ─ ネイティブ実装前提

FanHive ウィジェット帳

既存のカレンダーアプリと推し活アプリを見て組み立てた案です。 25種類、ホーム画面の小中大からロック画面・StandBy・コントロールまで。 すべて実寸の比率で描いてあるので、何件入るかがそのまま判断できます。

テーマ（外皮）はウィジェットに降ろさず、背景画像だけ自由にします。 参考にした2つ。Oshibanaは「推しの画像＋あと何日」をホームにもロックにも置ける形で、 推し活の定番になっています。ジョルテが支持されている理由は見やすさと ウィジェットごとに設定を変えられること。同じ種類を2つ置いて別々の中身にできる、 これが効いています。

A

逃さない

このアプリの芯です。受付の締切を逃すのがいちばん痛いので、発売日より締切を先に出します。 残り日数は端末の中の計算だけで出せるので、通信なしで更新できるのも都合がいい。

かゆいところ。受付開始は「10:00から」のように時刻まで決まっていることが多い。 当日になったら「あと2時間14分」に自動で切り替える。開始10分前から色を変える。 ここまでやると「これのために入れた」になります。

B

愛でる

推しで画面を埋めるための面。情報より絵が主役で、日付は小さく添えるだけ。 ここが「撮って上げたくなる」層なので、外皮（見た目のテーマ）がいちばん効きます。

記念日はアプリの中に無いデータ（キャラの誕生日、推し始めた日）なので、 使う人が自分で入れる欄が要ります。Oshibana はここを主戦場にしていて、 30日前・5日前・1日前に知らせる作りになっています。

C

見渡す

カレンダーアプリの領分。ジョルテの評価が高いのは密度と見やすさなので、 月表示は「予定のある日に作品色の点」だけに絞って、文字を詰め込まない方向にします。

特大は iPhone に無い枠です。 iOS の特大（systemExtraLarge）は iPad と Mac だけで、iPhone では選べません。 Android は自由に伸ばせるので、横長に広げれば同じものが置けます。 iPhone 向けには、同じ発想を縦に畳んだ「月＋直近3件」を用意しています。

D

その場で動く

iOS 17 以降はウィジェットの中のボタンが押せます（App Intents）。 アプリを開かずに済むものだけをここに置きます。

「予約した」を押せるのが効きます。 予約を済ませたものが締切一覧に残り続けるのは、いちばん邪魔なノイズです。 ホーム画面から1タップで消せると、一覧が常に「まだやってないこと」だけになる。

E

ロック画面・StandBy・コントロール

ホーム画面より見る回数が多いのがロック画面です。情報を1つに絞る代わりに、 1日に何十回も目に入ります。StandBy は充電中の横向き表示で、枕元の時計になります。

作るときに決めておくこと

ウィジェットごとに設定を持たせる

ジョルテが支持されている核心がこれです。同じ種類を2つ置いて、中身を別にできる。 「ちいかわ用」と「ハイキュー用」を並べて置けると、置く楽しみが生まれます。

  • 作品でしぼる … 全部／フォロー中／特定の1作品
  • 何を出すか … 締切だけ／発売だけ／両方／いいねしたものだけ
  • 表示件数 … 中サイズで2〜4件、大で5〜8件
  • 背景 … 塗り／半透明／推しの画像／なし（壁紙を透かす）
  • 見た目 … 外皮（現行／PANEL／SURGE、将来は生成したもの）

更新の重さで2つに分ける

種類更新のしかた頻度
カウントダウン系端末内の日付計算だけ。通信不要1日1回の予定表を先に配れば十分。当日は分単位も可
一覧・カレンダー系アプリ側が保存したデータを読むアプリを開いたとき＋1日数回
値下げ通知が来たときに書き込む出来事があったときだけ

iOS も Android もウィジェットの更新回数には上限があります。 時計のように動いて見えるのに通信していないカウントダウンを主役にすると、上限に当たりません。

色だけで意味を伝えない

iOS には、ウィジェットの色を抜いて壁紙の色で染めるモードがあります（ロック画面や、ホームの着色表示）。 作品ごとの色は、その状態では消えます。 色に加えて、線の太さ・形・位置でも区別が付くようにしておく必要があります。

Android の寸法

Android は自由な大きさに伸ばせるので、2×2 / 4×2 / 4×4 の3つを基準に作り、 間の寸法では件数が増減するだけにします。iOS の小・中・大とほぼ対応します。

テーマは降ろさない。背景画像だけ自由にする

決定。ウィジェットにはアプリの外皮（生成したテーマ）を適用しません。 代わりに背景画像をウィジェットごとに自由に設定できるようにします。

こうすると、いちばん厄介だった問題が消えます。ネイティブで組む場合 書体はアプリに同梱したものしか使えないので、テーマを降ろすと 「色は合っているのに書体が合っていない」中途半端な状態になる。これがいちばん壊れて見えます。 やらないほうが綺麗です。

同梱する書体は2つで足ります。数字に Big Shoulders Display （太い圧縮体は写真の上でも粘る）、和文に BIZ UDPGothic （UD設計なので小さくても崩れない）。点で組む書体は写真の上で読めなくなるので使いません。

背景画像で必ず起きること：文字が読めなくなる

推しの画像は明るくてカラフルなので、その上に白文字を置くと消えます。ここは先に設計します。

  • 画像の明るさを測って、暗幕の濃さを自動で決める。明るい画像には濃く、暗い画像には薄く
  • 暗幕は全面ではなく文字が乗るところだけ（下半分など）。推しの顔を潰さない
  • 濃さは使う人が調整できる（0〜80%）。「顔を見せたい」と「日付を読みたい」の綱引きは本人にしか決められない
  • 極端に明るい画像なら、文字を白から黒に自動で切り替える

切り取り位置を選べるようにする

ウィジェットは正方形・横長・縦長で比率が違うので、同じ画像でも切り取られる場所が変わります。 顔が切れると台無しなので、位置を指定できる欄が要ります。 アプリの背景画像設定にある bgImageOffsetX / bgImageOffsetY と同じ考え方が使えます。

背景の選択肢は4つ

  • なし … 塗り。いちばん読みやすい
  • 半透明 … 壁紙が透ける（ジョルテの作法）
  • いいねしたものから選ぶ … 公式の告知画像。アプリの中にもう入っているので手間ゼロ
  • 自分の画像 … 端末の写真から

実装で気をつけること

元画像をそのまま渡さない。ウィジェットの拡張が使えるメモリは厳しく制限されていて （iOS で30MB程度が目安）、高解像度の写真をそのまま読むと落ちます。 保存する時点でウィジェットの寸法に合わせて縮小したものを作り、それを渡します。

置き場所は iOS が App Group、Android が内部ストレージ。サーバーには送りません。 版権は使う人の側に置いたままにする、という線引きがそのまま生きます。

課金の置きどころ

  • 無料 … 小サイズ2種類（次の締切・今日）を1つずつ
  • プレミアム … 全種類・複数配置・ウィジェットごとの設定・ロック画面・StandBy
  • 置く数が増えるほど価値が積み上がるので、続ける理由になります
